# Suzukuri 0.2.2

## Summary

0.2.2 is a patch release of the 0.2.1 command-contract and repository
initialization work. It also makes release verification independent of the
target package version already being published, so the package can be
validated before the GitHub Release triggers npm publication.

## Added

- Ordered `steps` command definitions in `.suzukuri/commands.json`, alongside
  the existing single-`argv` producer form. Steps execute in declared order
  over the existing bounded process execution primitive and stop on the first
  failed/signaled step, matching `&&` aggregate semantics.
- Structural per-step failure identification for `suzukuri verify`: the
  failing step is reported from execution structure (declared step
  name/order), not inferred from concatenated producer output.
- Deterministic execution-result reuse for multi-step command definitions:
  the existing semantic-result cache key now covers step name, order, and
  argv, so changing any step invalidates reuse for that command.
- `suzukuri init`: an interactive repository-adoption flow that detects the
  supported Node.js/pnpm or npm ecosystem, imports safely representable
  package scripts into `.suzukuri/commands.json`, and applies the accepted
  migration only after explicit confirmation.

## Changed

- Suzukuri's own `.suzukuri/commands.json` and the Wabachi repository use the
  ordered-steps command contract through `suzukuri test` and `suzukuri verify`.
- `suzukuri skill` scenarios are projected directly from the command contract,
  keeping scenario usage and help text synchronized with the command surface.
- `--format` now defaults `skill` output to human-readable text; use `--json`
  or `--format json` for the automation contract.

## Fixed

- Release-time `suzukuri init` lockfile verification no longer depends on the
  unreleased target version being available from npm.
- The stale npm `package-lock.json` was removed; `pnpm-lock.yaml` remains the
  repository's canonical lockfile.

## Breaking changes / migration

None.

## Upgrade

```bash
npm install --global suzukuri@0.2.2
suzukuri --version
suzukuri init
```

Expected version output:

```text
0.2.2
```

## Release verification

Publishing is triggered by GitHub Release `v0.2.2` and uses npm Trusted
Publishing through the repository's release-triggered publish workflow. The
workflow rebuilds, tests, packs one tarball, runs
`scripts/verify-release-certification.mjs` against it (release tag, checked-
out source SHA, and tarball digest all match), smoke-tests that same tarball,
and publishes those bytes to npm.
