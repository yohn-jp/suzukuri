# Suzukuri 0.3.0

## Summary

0.3.0 makes repository verification incremental and evidence-aware. Repositories
can explicitly scope verification inputs and classify verification tiers;
stepped verification reuses unchanged results independently; and reusable
results carry deterministic evidence that another agent or session can validate
without rerunning the producer.

The release also hardens source provenance, CLI input boundaries, Git path
identity, and TypeScript source-kind admission. The packed-package release suite
now certifies the incremental verification path through the installed CLI.

## Added

- Explicit verification tiers: `iteration`, `focused`, and
  `authoritative`. Tiers are repository-declared metadata; Suzukuri does not
  infer or select them.
- Explicit `inputs` scopes for repository commands and individual verification
  steps. Scoped fingerprints include tracked and non-ignored untracked content
  selected by the declaration; omitted scopes retain conservative
  repository-wide fingerprinting.
- Independent step-level reuse for stepped verification. Unchanged PASS and
  FAIL results can be reused without spawning their producers while changed
  steps execute normally.
- Canonical reusable verification evidence containing deterministic producer,
  input, result, and evidence identities plus `executed`/`reused` state and
  declared tier metadata.
- Packed installed-package certification covering tier propagation, scoped
  invalidation, producer-definition invalidation, PASS/FAIL reuse, evidence
  identity stability, and cached-failure short-circuit behavior.

## Changed

- Source provenance now always includes a SHA-256 digest computed from the exact
  projected source bytes. A caller-supplied `hash` is treated as a claim and
  must match the computed digest.
- CLI source input is bounded to 10 MiB independently of projection output
  budgets. Regular files are size-checked before full allocation where
  possible, and stdin is accumulated incrementally.
- CLI option parsing now rejects unknown options and keeps parse-time failures
  inside the structured diagnostic boundary.
- The TypeScript source adapter explicitly admits TypeScript/TSX source kinds
  and rejects unsupported source identities/media types rather than silently
  treating them as TypeScript.

## Fixed

- Negative option values such as `--budget -5` now reach numeric validation
  instead of being retokenized as option names.
- Git path projection preserves legal literal backslashes instead of rewriting
  them as path separators.
- Git C-style quoted path decoding rejects incomplete terminal escapes and
  octal values outside the byte range instead of coercing them.
- Caller-provided source hashes can no longer forge authoritative provenance.

## Breaking changes / migration

No command has been removed, but 0.3.0 intentionally tightens invalid-input
handling:

- unknown CLI options that were previously ignored now fail;
- CLI profile/project source input larger than 10 MiB now fails before
  projection;
- JavaScript-family and other unsupported source kinds are rejected by the
  TypeScript source adapter;
- a supplied source `hash` must match the SHA-256 digest of the exact source
  content.

Repositories using verification reuse can add explicit `inputs` and `tier`
metadata incrementally. Omitting `inputs` preserves repository-wide
fingerprinting.

## Upgrade

```bash
npm install --global suzukuri@0.3.0
suzukuri --version
suzukuri --help
```

Expected version output:

```text
suzukuri 0.3.0
```

## Release verification

Before merge, the release branch must pass `pnpm run verify`. Package
verification builds and packs Suzukuri, installs the tarball into an isolated
consumer, and exercises the installed CLI, including the 0.3.0 incremental
verification/evidence contract.

After merge, GitHub Release `v0.3.0` triggers the canonical npm Trusted
Publishing workflow. The workflow rebuilds and tests, packs one tarball,
certifies that the release tag, checked-out source SHA, and tarball SHA-256
match, smoke-tests that same tarball, and publishes those exact bytes to npm.
